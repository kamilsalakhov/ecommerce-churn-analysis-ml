# Прогнозирование оттока клиентов e-commerce

Учебный ML-проект на Python по датасету `E Commerce Dataset.xlsx`. Проект показывает базовый полный пайплайн для задачи бинарной классификации: от первичного анализа данных до сохранения обученной модели.

## Цель проекта

Построить модель машинного обучения для прогнозирования оттока клиентов e-commerce-сервиса и объяснить, какие признаки сильнее всего связаны с уходом клиентов.

Целевая переменная:

- `Churn = 0` — клиент остался;
- `Churn = 1` — клиент ушёл.

## Описание датасета

Данные находятся в папке `data`. В таблице есть информация о клиентах: срок использования сервиса, устройство входа, способ оплаты, город, жалобы, количество заказов, дни с последнего заказа, кешбэк, удовлетворённость и другие признаки.

Идентификатор `CustomerID` не используется как обучающий признак.

## Этапы анализа

1. Загрузка Excel-файла из папки `data` через `pandas` и `openpyxl`.
2. Первичный осмотр данных, проверка пропусков и дубликатов.
3. EDA с графиками распределений, связей признаков с `Churn` и корреляционной матрицей.
4. Проверка гипотез статистическими тестами.
5. Предобработка данных через sklearn `Pipeline`.
6. Обучение моделей классификации.
7. Подбор гиперпараметров лучшей модели через `GridSearchCV`.
8. Интерпретация важности признаков.
9. Сохранение финального pipeline через `joblib`.

## Использованные модели

- Logistic Regression;
- Decision Tree;
- Random Forest;
- Gradient Boosting.

XGBoost не используется, чтобы не добавлять лишние зависимости.

## Итоговая лучшая модель

Лучшей моделью в базовой версии стала `Random Forest`. Подбор гиперпараметров был выполнен, но финальной оставлена версия с лучшим F1-score и recall для задачи оттока. Финальный pipeline сохранён в файл:

```text
models/best_churn_model.pkl
```

## Основные выводы

- Клиенты с коротким `Tenure` чаще попадают в отток.
- Наличие жалобы (`Complain`) заметно связано с повышенным риском ухода.
- Поведенческие признаки вроде `DaySinceLastOrder`, `OrderCount`, `CashbackAmount` и `CouponUsed` помогают модели лучше оценивать риск оттока.
- Для churn-задачи важно смотреть не только на accuracy, но и на recall, F1-score и ROC-AUC.

## Как запустить проект

1. Создать и активировать виртуальное окружение.
2. Установить зависимости:

```bash
pip install -r requirements.txt
```

3. Открыть ноутбук:

```bash
jupyter notebook notebooks/ecommerce_churn_analysis.ipynb
```

4. Выполнить ячейки сверху вниз.

После выполнения ноутбука модель будет сохранена в папку `models`.
